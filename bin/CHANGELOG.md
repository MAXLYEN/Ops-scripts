# 版本迭代记录

各文件独立编号。本次按现有头注释建立目录记录；旧注释未标日期的版本保持日期未记载，不补造历史。

## 2026-09-25：更新检查

生产机切到 `v2026.09.25.1` 后，一键巡检的脚本盘点显示 35 个已装脚本里 22 个落后于固定版本 —— `--pin` 与 `-u` 只换引导器、公共库和菜单，已装脚本各自停在当初装的版本，其中 `panel-backup-upload`、`sync-llm-allowlist` 等几个旧版有实际风险，却没有任何地方提示。

| 文件 | 原版本 → 当前版本 | 变更 |
| --- | --- | --- |
| `opsget` | 1.5.1 → 1.6.0 | 新增 `--outdated`：把工具箱本身（`opsget`、`opsbox`、公共库）和 MANIFEST 里每个已装脚本与当前 ref 逐个比内容，stdout 每行「路径、本地版本、该 ref 的版本」供菜单解析，说明走 stderr；拉不到 MANIFEST 时以非 0 退出 |
| `opsbox` | 1.1.0 → 1.2.0 | 启动时后台检查更新，头部显示结果（检查中 / 发现 N 个更新 / 已是最新 / 检查失败），有更新时主菜单出现 `[u] 一键更新`；缓存 5 分钟，换固定版本即作废；`--check-updates` 同步检查一次。工具箱设置新增「更新已装脚本」（可挑着更新），「更新工具箱」后顺便问要不要检查。定时任务在用的脚本标出来并提醒更新后手动跑一次；菜单本身更新后自动重新载入。主菜单回车为刷新。本机脚本盘点的说明不再写「看版本有没有落后」——它只列版本不比较。测试机试用后又修三处：一键更新后立刻重新检查（原先头部停在「还没检查」）；逐项填写先算缺哪些再补键，模板带默认值的项（如 `MYSQL_DEFAULTS_FILE=/root/.my.cnf`）也摆出来、回车保留，不再悄悄填好后说「都填好了」；终端退格键发来的 `^H` / DEL 按删除处理（原先「输 3 再删掉」成了认不出的选项，填配置时还会把 `^H` 存进文件）。之后又发现只在回车后处理 `^H` 不够：屏幕上仍回显一串 `^H`，看着有内容、实际是空，在初始化向导里回车就触发了阶段 00（会 `apt upgrade`）。改为所有可见输入都用 `read -e` 行编辑，`^H` 与 DEL 都真正删掉字符，看到什么就是什么；初始化各阶段执行前必须确认（默认不执行）。又按测试机反馈定下规则「回车永远不执行」：所有确认一律 `[y/N]`（原有 29 处，其中一键更新、重新执行、运行备份等默认「是」），选择类菜单去掉默认项（配置管理、立即备份、VPS 采集 / 评分、更新已装脚本），更新工具箱、new-api 链路检查（可能重启隧道）、密钥登录、批量下发公钥执行前先确认，Vaultwarden 升级前的备份改为固定步骤；lint 检查确认提示不再带默认值。卸载：先问要不要连配置一起删（回车＝保留），执行前停掉后台更新检查（否则删完会被写回），卸完直接退出菜单 |

## 2026-09-25：新机器上的配置引导

真机试用发现：新机器没有 `env.conf` 时，一键巡检里「监控指标库体检」「本机脚本盘点」没被跳过，而是执行后立刻报「缺少配置文件」退出。这两个脚本没声明配置键，opsget 当它们「裸机可跑」，但开头的 `load_env` 要求 `env.conf` 存在 —— 16 个脚本都是这样。

| 文件 | 原版本 → 当前版本 | 变更 |
| --- | --- | --- |
| `opsget` | 1.5.0 → 1.5.1 | 会 `load_env` 的脚本：没有 `env.conf` 时执行前预检拦下、`-e` 说明要有文件、`-c <路径>` 与 `-c` 建出空的 `env.conf`（不放宽任何脚本：清理类靠配置里的保护名单，不能无配置照跑）。读云端声明的函数不再经 `$(...)` 取值：原先里面的 `die` 只退出子 shell，拉取失败会被当成「不需要配置」 |
| `opsbox` | 1.0.0 → 1.1.0 | 执行前先装好脚本并检查配置，缺什么当场逐项问：显示模板里的中文说明，凭据类输入不回显，值用单引号原样保存，路径不存在时提醒，回车跳过并告诉以后去哪补；不再打开编辑器。配置管理改为「逐项填写本机还没填的」「查看当前配置（凭据打码）」，编辑器降为高级选项。头部提示已装功能还有几项没填；一键巡检有跳过项时说明怎么启用，本机没有的服务（如没有 MySQL 时的监控库体检）记为「不适用」而不是异常；选项输入容错：去首尾空格、全角转半角，认不出时明确提示「没有这个选项」而不是默默刷新（真机上第一次按 `a` 没反应），说明卡片上全角 `０` 不再被当成回车而误执行；40 位提交号只显示前 12 位 |

## 既有版本（日期未记录）

### `opsget`

- **1.3.1**：两处修正。① -e / -c <路径> 改为**云端优先**读声明 —— 原来优先读本地已装
  副本，而本地可能是旧版；旧版少一行声明会得出「不需要配置」，这个方向的
  错答比误报缺配置危险得多。② 声明支持 `A|B` 二选一，任一有值即通过，
  用于「新键 + 旧键回落」（如 BACKUP_PASS_FILE|VW_PASS_FILE）——
  否则脚本内部明明有回落，opsget 却会按字面拦下来。
- **1.3.0**：配置按需化。脚本头部用 `# ENV-REQUIRED: KEY1 KEY2` 声明自己必填的键，
  opsget 据此按需预检、按需生成 env.conf。不声明 = 声明「裸机能跑」。
  起因：无差别检查 env.conf 是否存在，会对 init/、vpsscore 这类刻意不依赖
  配置的脚本发假警告；而真正缺键时又只能等脚本自己跑到一半才报。
  顺带把 -h 改成 usage() 函数 —— 原来 sed 按行号切注释，改头部就会切歪。
- **1.2.1**：拉取加 cache-buster —— raw.githubusercontent 有约 5 分钟 CDN 缓存，
  「云端改完这边重新拉一次就生效」在这段窗口里是假的。而改完立刻验证
  恰恰是最常见的场景，拿到旧版会让人误判成「改了没效果」去改代码。
- **1.2.0**：拉取加重试 —— 实测遇到过 DNS 瞬时解析失败（Could not resolve host），
  一次失败就放弃会让「云端是唯一来源」这件事变得不可靠
- **1.1.0**：记录安装台账到 /var/lib/ops-scripts/installed.list，供清理脚本精确回收
